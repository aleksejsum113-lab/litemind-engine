# Архитектура LiteMind Engine

## Общая схема

```
┌────────────────────────── LiteMind Desktop (Electron) ──────────────────────────┐
│  packages/app (SolidJS UI)                    packages/desktop (main)           │
│  ┌──────────────────────────────┐             ┌─────────────────────────────┐   │
│  │ Чат OpenCode (сессии, файлы, │             │ litemind-host.ts:           │   │
│  │ терминал, проекты)           │             │  автозапуск движка в main-  │   │
│  │ Нативные экраны LiteMind     │   HTTP      │  процессе (порт 8399)       │   │
│  │ /litemind?section=...        │────────────▶│ OpenCode sidecar (порт      │   │
│  │ Модели/Каталог/Загрузки/     │ 127.0.0.1   │ по выбору) — чат/агент      │   │
│  │ Железо/Мониторинг/Настройки  │             └─────────────────────────────┘   │
│  └──────────────────────────────┘                                               │
│            │ переключатель моделей                                              │
│            ▼ packages/core → plugin/provider/litemind.ts (GET /v1/models)       │
└────────────┼────────────────────────────────────────────────────────────────────┘
             ▼
   litemind-engine (порт 8399, в процессе Desktop)
   ├── api/server.js        — OpenAI-совместимый API + роуты LiteMind
   ├── adaptive/controller  — классификация, уплотнение контекста, дайджесты
   ├── adaptive/capabilities— честная карта возможностей runtime
   ├── adaptive/project-index— индекс и поиск по проекту
   ├── optimize/optimizer   — автооптимизация (потоки, tokens/sec, TTFT)
   ├── core/engine.js       — очередь, memory-gate, таймауты, отмена, выгрузка
   ├── resource/            — sampler метрик, gate бюджета, приоритеты
   ├── catalog + compat     — 12 моделей GGUF, зелёный/жёлтый/красный
   ├── download + install   — Range-загрузчик и установка в Ollama (blobs/create)
   └── backends/ollama.js   — HTTP к Ollama 127.0.0.1:11434 (модели не удаляются)
```

## Поток пользовательского сценария

1. **Установка** → NSIS создаёт ярлыки «LiteMind Engine».
2. **Первый запуск** → Electron main поднимает движок (`startLiteMindEngine`),
   если он уже не запущен (порт 8399 занят — переиспользуем).
3. **Обнаружение железа** → `GET /api/hardware`: CPU/AVX (3 метода), RAM, GPU, диски.
4. **Каталог → загрузка → установка** → `POST /api/downloads` (Range, пауза/отмена),
   `POST /api/install` (sha256 → blob → create, NDJSON-статусы).
5. **Выбор модели** → переключатель OpenCode видит `/v1/models` через
   LiteMind-провайдер (как Ollama/LMStudio).
6. **Реальный ответ** → `POST /v1/chat/completions` → adaptive-контроллер
   (классификация, уплотнение, бюджет) → очередь → memory-gate → Ollama.
7. **Повторный запуск** → настройки и профили производительности читаются из
   конфига (`%APPDATA%/LiteMind/config.json`), модели остаются в Ollama.

## Ключевые решения

- **Движок в процессе Desktop**: нет второго сервиса и терминала; ошибка движка
  не валит приложение (разделы показывают понятный оффлайн-баннер).
- **Провайдер-плагин вместо форка чата**: LiteMind-модели появляются в
  переключателе стандартным механизмом local-provider (как ollama.ts/lmstudio.ts).
- **Ноль зависимостей движка** (только node:) — маленький asar, быстрый старт.
- **Никаких скрытых переключений моделей**: рекомендации «квант поменьше / модель
  полегче» показываются пользователю, выбор всегда за ним.
