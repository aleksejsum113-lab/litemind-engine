# Adaptive Engine — как движок облегчает работу модели

Принцип: **минимально необходимая нагрузка без потери качества**. Каждый механизм
ниже либо измеряем, либо честно помечен как недоступный.

## 1. До генерации (`adaptive/controller.js`)

| Механизм | Что делает | Честность |
| --- | --- | --- |
| Классификация сложности | `simple/file/project/hard` по эвристикам (файлы, код, объём) | `method: 'heuristic'`, нулевая нагрузка — не тратим RAM на вторую модель |
| Бюджет генерации | simple → ×0.5 (но ≥192 ток.), hard/project → ×1.25–1.5 | Поверхностные ответы на сложные задачи исключены (`minOutputTokens`) |
| Уплотнение контекста | system + первая задача пользователя + последние N сообщений сохраняются; середина → сводка-заглушка | Сводка помечена как `[Сжатая история…]`, факты первых 160 символов сохранены |
| Дайджест длинного входа | extractive-сжатие до 60% контекста: головка, факты (цифры/код/требования), хвост | Факты сохраняются дословно; обрезка объявляется в тексте |
| Prompt caching | стабильный system-префикс → llama.cpp переиспользует KV | Только то, что реально поддерживает runtime |

## 2. Подбор конфигурации (`optimize/optimizer.js`)

- При первом запуске модели: 3 пробы потоков (профиль/половина/минимум) на коротком
  промпте через полный конвейер (очередь + memory-gate), выбирается быстрейшая по
  tokens/sec, сохраняется в `config.optimizations` (`%APPDATA%/LiteMind/config.json`).
- Повторные бенчмарки не запускаются автоматически — только по кнопке «Автооптимизация».
- Живые метрики (EMA tokens/sec, TTFT, число запросов) копятся автоматически.
- При скорости < 2.5 ток/с движок советует: квант поменьше → модель 0.5B–1.5B →
  профиль «Бережный». **Модель не переключается скрытно.**

## 3. Защита Windows (`core/engine.js`, `resource/`)

- **Memory-gate до запуска**: веса + KV (64 КБ/токен) + 15% оверхед ≤ доступная RAM
  с резервом профиля (2048/1024/768 МБ). Не влезает → 503 с объяснением.
- **Контроль памяти во время генерации**: каждые 2 с; при >90% RAM генерация
  прерывается, модель безопасно выгружается, пользователь получает `MEMORY_OVERLOAD`.
- **Очередь**: maxConcurrentRequests (1/2/2 по профилям), лимит очереди, таймауты,
  отмена, idle-выгрузка моделей (5/10/15 мин).
- **Приоритет процессов**: «Бережный» → Ollama BelowNormal (Windows) / renice (Linux).

## 4. Возможности runtime (`adaptive/capabilities.js`)

| Технология | Статус для Ollama | Почему |
| --- | --- | --- |
| Prompt cache (stable prefix) | ✅ включена | llama.cpp кэширует общий префикс автоматически |
| Chunked prefill | ✅ (runtime-auto) | управляется llama.cpp; движок держит num_batch в безопасных пределах |
| mmap | ✅ включён | экономия RAM; mlock выключен — на 16 ГБ вреден |
| Speculative decoding | ❌ | Ollama API не поддерживает draft-модель |
| Prompt lookup decoding | ❌ | не пробрасывается Ollama API |
| KV-cache Q8/Q4 | ❌ | type_k/type_v недоступны через Ollama API (план: прямой llama.cpp-адаптер) |

## 6. Project Context (`adaptive/project-index.js`)

- Инкрементальный индекс (size+mtime, до 4000 файлов, node_modules/.git пропускаются),
  извлечение сигнатур функций/классов (JS/TS/Py/Go/Rust/Java/C).
- Поиск релевантных фрагментов под запрос (токены → файл/символ/содержимое),
  отдача сниппетов ±6 строк — в контекст модели попадает только нужное.
- API: `POST /api/project/scan`, `GET /api/project/search?q=&path=`, `GET /api/project/map`.
