# Безопасность LiteMind Engine

## Модель доступа

Правила реализованы в `checkAccess()` (`src/api/server.js`) и покрыты автотестами:

| Клиент | Конфигурация | Результат |
|---|---|---|
| loopback (`127.0.0.1`, `::1`) | любая | разрешено — локальный доступ по умолчанию |
| внешняя машина | `allowLan: false` (по умолчанию) | **403** «only local clients» |
| внешняя машина | `allowLan: true`, аутентификация не настроена | **403** «authentication is not configured» |
| внешняя машина | `allowLan: true`, неверный/отсутствующий токен | **401** |
| внешняя машина | `allowLan: true`, верный токен (`Authorization: Bearer …` или `?token=`) | разрешено |

Дополнительно `validateConfig()` **отклоняет** конфигурацию, где `allowLan: true` указан без
`auth.enabled` и токена: открыть сервер в локальную сеть без аутентификации нельзя даже
ошибочно.

По умолчанию сервер слушает только `127.0.0.1` (не `0.0.0.0`), порт 8399.

## Секреты

- LiteMind **не содержит** секретов: ни API-ключей, ни облачных токенов, ни телеметрии.
- Токен доступа задаётся только пользователем в `%APPDATA%\LiteMind\config.json`.
  Файл создаётся с правами текущего пользователя; пароль в код не зашит и в репозиторий
  не попадает (рекомендуется не коммитить `config.json`).
- Ollama работает локально и не требует ключей.
- Запросы наружу (в интернет) проект не выполняет вообще.

## Границы доверия

- **Доверяется:** loopback-клиенты. Любой локальный пользователь ОС потенциально может
  обратиться к `127.0.0.1`. Это осознанный компромисс, соответствующий ТЗ («только локальным
  клиентам по умолчанию»); для более строгого режима используйте `allowLan + auth`.
- **Не доверяется:** всё остальное. Проверка выполняется для **каждого** запроса, включая
  статику панели (которая, впрочем, не содержит данных).
- **Тело запроса** ограничено 1 МиБ — защита от исчерпания памяти большим payload.
- **Панель** — статические файлы без сборки и без внешних CDN: никаких сторонних скриптов.

## Обработка процессов и данных

- Сторонние процессы Windows **никогда не завершаются**. В коде нет `taskkill`, `kill -9`
  и аналогов; единственный «жёсткий» эффект — закрытие собственного HTTP-соединения
  с Ollama, что прерывает генерацию на стороне backend'а.
- Идентификаторы процессов не используются: LiteMind не владеет процессом Ollama и не
  претендует на его управление.
- Журнал (`%APPDATA%\LiteMind\logs\*.jsonl`) содержит технические события: время, уровень,
  тексты ошибок, идентификаторы запросов и имена моделей. **Промпты и ответы пользователей
  в журнал не пишутся.** Персональные данные не собираются и не передаются.
- Панель показывает только локальные метрики (RAM/CPU/VRAM, состояние очереди).

## Проверка конфигурации на небезопасные значения

`validateConfig()` запускается при каждом старте и блокирует:

- `api.allowLan` без включённой аутентификации;
- неверный порт;
- неизвестный профиль;
- неизвестный backend и некорректный URL.

## Ограничения v0.1 (честно)

- HTTPS не реализован: трафик идёт по loopback, шифрование не требуется; при `allowLan`
  токен передаётся открытым HTTP — **не используйте LAN-режим через ненадёжные сети**.
- Нет rate limiting помимо лимита очереди (16 в профиле low) — для loopback это избыточно.
- Нет разграничения пользователей: loopback-доступ общий для всех учёток машины.
