# Минимальный тест реальной модели (запустить позже, когда компьютер свободен)

Это **не нагрузочный тест**: установка, один короткий запрос, проверка выгрузки, остановка.
Ничего из этого не выполняйте, пока не дано **отдельное разрешение**.

Что **запрещено до разрешения**: устанавливать Ollama, скачивать модели, запускать
генерацию и нагрузочные тесты. Остальное (автотесты `npm test`, `doctor`, открытие панели)
безопасно — оно работает на mock-данных.

---

## 0. Совместимость: проверено заранее

| Параметр | Ваше значение | Требование Ollama | Итог |
|---|---|---|---|
| ОС | Windows 11 Pro, сборка 22631 (23H2), 64-бит | Windows 10 22H2 или новее, Home/Pro | ✅ подходит |
| Процессор | Intel Celeron N5095A, 4 ядра / 4 потока, 2.0 ГГц | 64-битный CPU | ✅ подходит |
| Инструкции CPU | Jasper Lake **без AVX/AVX2** | с версии Ollama **0.1.21** (январь 2024) есть авто-выбор варианта AVX2 / AVX / без AVX для Windows | ✅ подходит |
| ОЗУ | 16 ГБ (usable 15.78 GiB) | рекомендуется от 8 ГБ | ✅ хватает с запасом |
| Видео | Intel UHD Graphics (встроенная, ~1 ГБ общей памяти) | GPU необязателен | ✅ работает на CPU |
| Диск C: | **12.1 ГБ свободно** из 117.1 ГБ | рекомендуется ~10 ГБ свободно под Ollama | ⚠️ хватает, но тесно |
| Диск E: | **80.8 ГБ свободно** из 119.2 ГБ | — | ✅ запас есть |

Реальный независимый тест такой же платформы (Celeron N5095 + Ollama 0.32.1) даёт
ориентир скорости: **≈ 7–8 токенов/сек** на модели 0.5–0.6B при 4 потоках
(при 2 потоках ждите ≈ 4–6 ток/с — зато система остаётся отзывчивой).
Источник: https://unland.dev/blog/youyeetoo-x1s-ollama-llamacpp-matched-retest

⚠️ При длительной генерации процессор нагревается (в том тесте — до ~80–85 °C).
Если вентилятор шумит или системa тормозит — остановите генерацию, это штатное поведение.

## 1. Свободное место (проверить перед установкой)

```powershell
Get-CimInstance Win32_LogicalDisk -Filter "DriveType=3" |
  ForEach-Object { "{0}  свободно {1:N1} ГБ из {2:N1} ГБ" -f $_.DeviceID, ($_.FreeSpace/1GB), ($_.Size/1GB) }
```

Нужно **минимум 5 ГБ свободно на C:** (сама программа ≈ 1.5 ГБ + модель ≈ 0.4 ГБ +
запас). Если там меньше 5 ГБ — освободите место или заранее перенесите папку моделей
на E: командой ниже (это делается один раз при установке, это НЕ изменение настроек
LiteMind, а настройка самой Ollama):

```powershell
# только если C: почти полон: хранить модели на E:
[Environment]::SetEnvironmentVariable("OLLAMA_MODELS", "E:\ollama-models", "User")
```

Также нужно **минимум 4000 МБ свободной оперативной памяти** перед стартом:

```powershell
$os = Get-CimInstance Win32_OperatingSystem
"Свободно RAM: " + [math]::Round($os.FreePhysicalMemory/1KB) + " МБ из " + [math]::Round($os.TotalVisibleMemorySize/1KB) + " МБ"
```

## 2. Установка Ollama (вручную, только с разрешения)

Способ А — через winget:

```powershell
winget install --id Ollama.Ollama --accept-package-agreements --accept-source-agreements
```

Способ Б — вручную: скачайте https://ollama.com/download и запустите установщик.

Проверка, что Ollama действительно работает (перезапустите терминал после установки):

```powershell
curl.exe http://127.0.0.1:11434/api/version
# ожидаемый ответ: {"version":"0.x.x"}
ollama --version
```

Если ответа нет — найдите «Ollama» в меню «Пуск» (иконка в трее) и запустите.

## 3. Скачивание ОДНОЙ маленькой модели (с разрешения)

```powershell
ollama pull qwen2.5:0.5b
```

- размер загрузки ≈ **400 МБ**, в памяти ≈ 0.5 ГБ;
- специально маленькая — рассчитана на слабые машины;
- альтернатива для программирования (потом, не сейчас): `ollama pull qwen2.5-coder:0.5b`.

Проверка:

```powershell
ollama list
# ожидаемо: qwen2.5:0.5b   ...   ~400 MB
```

## 4. Конфигурация для слабого процессора (уже готова)

Файл: [config/litemind.low-spec.json](../config/litemind.low-spec.json)

| Параметр | Значение | Зачем |
|---|---|---|
| `maxConcurrentRequests` | 1 | один запрос — система не подвисает |
| `contextTokens` | 2048 | небольшой контекст |
| `maxOutputTokens` | 320 | короткий ответ |
| `cpuThreads` | 2 | 2 из 4 потоков — свободными остаются 2 под Windows |
| `idleUnloadSeconds` | 180 | выгрузка модели через 3 минуты простоя |
| `memoryReserveMb` | 3072 | 3 ГБ под Windows и встроенную графику |
| `maxRamUsageFraction` | 0.7 | отказ при прогнозе выше 70% всей RAM |
| `autoLoadAtStartup` / `allowAutoDownload` | false | ничего не запускается и не качается само |

Запуск LiteMind с этим конфигом (скрипт сам подхватывает `config\litemind.low-spec.json`):

```powershell
cd "/путь/к/litemind-engine"
.\scripts\start.ps1
# откроется панель: http://127.0.0.1:8399
```

Если не задать `LITEMIND_CONFIG`, используется `%APPDATA%\LiteMind\config.json`
(или значения по умолчанию, если файла ещё нет).

## 6. Минимальная реальная генерация (один запрос)

Вариант А — скрипт замеров (рекомендуется):

```powershell
node scripts\benchmark.mjs --model qwen2.5:0.5b --n 1
```

Вариант Б — вручную, короткий запрос:

```powershell
curl.exe -X POST http://127.0.0.1:8399/v1/chat/completions `
  -H "Content-type: application/json" `
  -d "{\"model\":\"qwen2.5:0.5b\",\"max_tokens\":64,\"messages\":[{\"role\":\"user\",\"content\":\"Привет, ответь одним предложением\"}]}"
```

Первый ответ приходит дольше остальных — модель грузится в память. Ожидаемо:
JSON с `choices[0].message.content`.

## 7. Проверка защиты слабого ПК

1. **Остановка.** В панели нажмите «Запустить», затем сразу «Остановить» — генерация
   прервётся, панель покажет «остановлено».
2. **Очередь.** Второй параллельный запрос получит `429` — один запрос за раз.
3. **Нехватка памяти.** При малом объёме свободной RAM запрос отклоняется с
   `MEMORY_BUDGET` — это защита, а не поломка.
4. **Выгрузка.** Нажмите «Выгрузить модель» в панели или:

```powershell
curl.exe -X POST http://127.0.0.1:8399/api/unload -H "Content-type: application/json" -d "{}"
```

Свободная RAM должна вернуться близко к исходной за 1–10 секунд (проверьте командой
из раздела 1 или «Диспетчер задач»).
