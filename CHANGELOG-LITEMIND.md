## [Unreleased] — Этап 2 «Глубокая оптимизация GGUF Runtime»

### Fixed
- **Обрыв генераций на 60-й секунде**: connect-таймаут в бэкенде жил весь стрим
  и убивал ответы длиннее минуты. Таймер теперь снимается сразу после
  заголовков ответа; генерацию сторожит watchdog бездействия, запускаемый
  от первого токена (медленный prefill длинного промпта больше не рвётся).
- **Таймауты запроса** подняты с 120/180/300 с до 600/900/1800 с: слабая
  модель на 2 т/с писала ответ 4–6 минут — прежние лимиты обрывали
  легитимные ответы. Автовыгрузка модели отодвинута до 15/30/60 мин простоя.
- **Параметры профиля применяются по-настоящему**: llama-server больше не
  переиспользуется с чужими настройками — при изменении потоков/batch/mmap/
  кэша/контекста (args-key) runtime честно перезапускается с новыми
  аргументами. Раньше автооптимизация потоков измеряла одну и ту же
  конфигурацию трижды (перезапуска не было).
- **Мониторинг CPU на Windows**: метрики переведены на чистый Node (os.freemem
  + дельта os.cpus). Раньше каждые 2 с запускался powershell с WMI-запросами,
  который на слабых машинах выходил за таймаут → CPU показывал 0% при
  работающей генерации (то, что пользователь и наблюдал).
- **numBatch игнорировался** — теперь передаётся в llama-server.

### Added
- **Трассировка стадий запроса** (§2): очередь → память → запуск runtime →
  промпт → первый токен → генерация, с честными «недоступно» для неизмеримого;
  `GET /api/perf`; разбор собственных таймингов llama.cpp (prompt eval /
  eval time) из stderr сервера; TTFT разделён на «с холодным стартом» и
  «после загрузки модели» — загрузка весов не выдаётся за медленную генерацию.
- **Профили с реальными параметрами** (§8): Бережный → 2 потока генерации на
  N5095A и приоритет ниже обычного; Сбалансированный → 3 потока + prefill на
  всех ядрах; Производительный → 4 потока, batch 2048, cache-reuse 256.
  Мониторинг показывает фактически применённые параметры и причину последнего
  перезапуска runtime.
- **mmap-политика «auto»** (§3): модели, заведомо помещающиеся в RAM
  (порог max(1 ГБ, 25% RAM)), грузятся без mmap — последовательное чтение
  быстрее холодного mmap на слабых дисках и ускоряет генерацию (веса уже в
  RAM); большие модели остаются на mmap, чтобы Windows могла вытеснять
  холодные страницы.
- **Динамический резерв RAM** (§3/§11): при признаках paging и высокой
  загрузке системы резерв для Windows растёт (до +50%), при спокойной системе
  равен базовому резерву профиля.
- **Диагностика в интерфейсе** (§12): панели «Runtime — фактически применённые
  параметры», «Стадии последнего запроса», расширенные средние по генерации;
  под ответом чата — честные замеры движка (загрузка модели, т/с, промпт).
- **Честная диагностика GPU** (§10): llama-server опрашивается через
  `--list-devices`; комплектная CPU-сборка честно сообщает «устройств нет»;
  автовключение iGPU не выполняется.
- **Приоритет по PID** сразу после запуска llama-server (§4/§11).
- **Сборка CI с вариантами ядер** (§4): GGML_BACKEND_DL + GGML_CPU_ALL_VARIANTS
  — база остаётся без AVX/AVX2 (совместимость с N5095A), но llama.cpp сам
  выбирает лучший поддерживаемый процессором вариант (на N5095A — sse42).

### Changed
- Потоки prefill (`--threads-batch`) — все ядра (короткая фаза), потоки
  генерации — по профилю (2/3/4 на N5095A).
- batch/ubatch по профилю 512/256, 1024/512, 2048/512 (раньше numBatch
  128–512 был ниже дефолтов llama.cpp и тормозил prefill).

## [0.6.0] — Этап 1В «Projects, Workspace и AI Terminal»

### Added
- **Проекты**: открытие папки с честной проверкой доступности (перемещённая или
  недоступная папка не становится активной и честно помечается), создание папки
  проекта через нативный диалог Windows (`mkdir -p`, корень диска запрещён),
  карточка активного проекта (имя, полный путь, состояние), закрытие проекта
  без удаления файлов, удаление проекта только из списка недавних (отдельно от
  удаления папки на диске), настраиваемые исключения сканирования.
- **Workspace — дерево файлов**: ленивое дерево (один уровень каталога за
  запрос — огромные проекты не грузятся в память), раскрытие/сворачивание
  папок, поиск файлов по имени с подсказками, служебные каталоги
  (`node_modules`, `.git`, скрытые) не показываются и не сканируются.
- **Workspace — поиск по содержимому**: поиск текста внутри файлов с номером
  строки и колонкой, бинарники и файлы больше 2 МиБ пропускаются, общий
  объём сканирования ограничен (32 МиБ), переход к файлу по клику.
- **Workspace — редактор**: индикатор несохранённых изменений «● не сохранено»,
  сохранение по Ctrl+S с проверкой mtime (409 при внешнем изменении файла с
  осознанным выбором «перезагрузить с диска» или «перезаписать поверх»),
  защита от потери правок при смене файла/проекта и при закрытии окна.
- **Контекст проекта для чата (§2)**: выбор файлов и папок кнопкой «＋ чат»,
  панель «Контекст для чата» показывает ровно то, что уйдёт модели; передача
  структуры проекта в чат одним нажатием; бинарные и слишком большие файлы
  уходят с честным предупреждением, а не молча; лимиты: 50 файлов, 120 тыс.
  символов на файл, 900 тыс. на контекст. Предупреждение о размере контекста
  относительно лимита модели (оценка, честно помеченная как приблизительная).
- **Изменения файлов через ИИ (§3)**: «Попросить ИИ изменить» прикладывает файл
  и шаблон инструкции; в ответе модели распознаются блоки ```file:…```;
  панель «Показать изменения» строит построчный diff (LCS, длинные совпадения
  сворачиваются); применение — только по явному подтверждению, перед записью
  автоматически создаётся резервная копия вне проекта
  (`<конфиг>/project-backups/`); кнопка «Восстановить из копии» возвращает
  исходник (и сохраняет ещё одну копию перед восстановлением — откат тоже
  обратим); конфликт mtime при применении не затирает внешние правки.
- **AI Terminal (§4)**: настоящий потоковый вывод (SSE) — stdout/stderr
  показываются по мере появления, а не после завершения; состояния готов /
  выполняется / останавливаю / остановлено / завершено (код N); «Остановить»
  с защитой от повторного нажатия и гонок; «Повторить» последнюю команду,
  «Очистить экран» с сохранением истории; лимит отображения 512 КиБ без
  потери полного вывода для чата; кодировки Windows определяются по факту
  (UTF-8 → CP866 → windows-1251) и сообщаются честно — русский текст CMD
  восстанавливается.
- **Связь компонентов (§5)**: открытие проекта синхронно переключает Workspace
  и рабочую папку Terminal; кнопки «Открыть папку», «Копировать путь»,
  «Обновить файлы проекта», «В чат →»; файл, выделенный фрагмент, структура
  проекта и вывод терминала передаются в чат только по явному действию
  пользователя.
- **API Этапа 1В**: `POST /api/project/open|create`, `GET /api/project/tree|
  find|grep|backups`, `POST /api/project/context|apply-change|restore-backup`;
  чтение файла отдаёт `mtimeMs`, запись принимает `expectedMtimeMs`/`force`;
  терминальный `exec` поддерживает потоковый режим (`stream: true`, SSE:
  start/stdout/stderr/error/exit).

### Security
- Все новые файловые маршруты проверяют, что путь внутри каталога проекта
  (`path.relative` + отказ от `..`), включая папки в контексте и backupId.
- Резервные копии хранятся вне проекта пользователя; автоматического удаления
  файлов нет нигде; содержимое проекта никуда не отправляется без явного
  действия пользователя.

## [0.5.0] — Этап 1 «Полноценный интерфейс и управление»

### Added
- **Собственная верхняя панель окна**: перетаскивание за заголовок, монограмма
  LiteMind, активная модель ровно по центру сверху, статус движка; область
  перетаскивания не перекрывает интерактивные элементы. Кнопки управления окном
  (свернуть / развернуть / восстановить / закрыть) — системный overlay Windows
  поверх нашей панели (frame:false + titleBarOverlay, высота 44 px).
- **Собственная иконка LiteMind** во всех местах: EXE, установщик NSIS,
  ярлыки, панель задач, окно (каналы prod/beta/dev). Элементы брендинга
  OpenCode из видимого интерфейса удалены.
- **История диалогов**: поиск по названиям и содержимому, сортировка по последней
  активности, дата/время у чатов, переименование, удаление только с
  подтверждением, выбранная модель сохраняется для каждого диалога.
- **«Новый чат» исправлен**: каждое нажатие создаёт отдельный новый диалог с
  собственным идентификатором; предыдущий диалог автоматически сохраняется;
  пустой диалог-заготовка не дублируется.
- **Менеджер моделей**: путь к файлу, формат, квантование, статус и действия —
  запустить / остановить / проверить файл (SHA-256) / открыть папку / сведения /
  удалить с подтверждением.
- **Загрузчик моделей**: диалог перед загрузкой (название, размер, источник,
  полный путь сохранения, свободное место, предупреждение при нехватке), выбор
  папки стандартным диалогом Windows (при первой загрузке и далее), автопроверка
  целостности после скачивания.
- **AI Terminal**: история команд (↑/↓), остановка выполняющейся команды
  (`/api/terminal/stop`), подтверждение опасных команд, передача вывода в чат.
- **Projects / Workspace**: выбор папки стандартным диалогом, недавние проекты,
  передача содержимого файла в чат как вложение.
- **Настройки**: «О приложении» (версии, пути), диагностика состояния, открытие
  журналов, выбор папки моделей/проекта через нативный диалог.
- Нативный IPC-мост: `pickFolder` (dialog.showOpenDialog), `shellOpenPath`,
  `shellShowItemInFolder`, `appInfo` — только от фреймов собственного рендерера.

### Fixed
- Повторное нажатие «Новый чат» больше не «теряет» создание диалога.
- Активный раздел и состояние боковой панели восстанавливаются после перезапуска.
- Версия сборки в CI берётся из `packages/litemind-engine/package.json`
  (источник истины), а не из захардкоженной строки workflow.

### Notes
- Переключатели веб-доступа и режима Chat/Agent в чате не показываются:
  функции появятся в этапах 4 и 5 (честный статус вместо декоративных кнопок).

## [0.5.1] — Этап 1Б «Каталог моделей, поиск и загрузчик GGUF»

### Added
- **Каталог v3**: 49 моделей / 171 GGUF из проверенных источников. У каждой
  записи — разработчик, назначение (9 категорий §2.1: программирование, общение,
  тексты, анализ, перевод, математика, длинный контекст, творчество,
  мультиязычность), лицензия, контекст, языки, размеры и LFS SHA-256 каждого
  файла, дата последней проверки сведений.
- **7 моделей Huihui** (ослабленные ограничения/abliterated): Qwen2.5 0.5B v3,
  Qwen3 1.7B, Qwen3.5 0.8B/2B/4B, Llama 3.2 3B, Qwen3 8B v2 — реальные
  публичные репозитории (кванты mradermacher, модели huihui-ai), размеры и
  SHA-256 сняты с Hugging Face API; ограничение характера честно описано
  («абсолютной свободы» не обещается). Dolphin и остальные записи сохранены.
- **Четырёхуровневая совместимость** (§2.3): подходит / подходит с
  ограничениями / не рекомендуется / несовместима. Учитываются архитектура
  (проверенные семейства runtime), требования AVX2, квантование, контекст,
  память (веса + KV-кэш ≠ размер файла) и скорость CPU.
- **Поиск и фильтры каталога**: по названию/разработчику/описанию; фильтры по
  назначению, размеру, квантованию, языку, контексту, RAM, совместимости CPU,
  типу модели, разработчику; сортировка по названию/размеру/специализации/
  дате проверки. Быстрый выбор по задаче: «Для программирования», «Для
  общения», «Для текстов», «Для анализа документов», «Универсальная» — с
  объяснением, почему модели подходят, без автопереключения модели чата.
- **Подробная карточка модели** и глоссарий терминов (GGUF, Q4/Q5/Q8, контекст,
  память ≠ файл, AVX). Неизвестные сведения показываются как «неизвестно».
- **Хранение моделей (§5.1/§5.2)**: при первой загрузке — рекомендация диска
  E: и нативный диалог выбора папки; выбранная папка сохраняется по умолчанию.
  В настройках — раздел «Хранение моделей»: папка, свободное место, общий
  размер моделей, перенос с копированием и сверкой SHA-256 (старые файлы
  сохраняются), проверка существующих путей, открытие папки.
- **Регистрация пользовательских GGUF (§6)**: «＋ Добавить свою модель» —
  нативный выбор файла (IPC `pickGgufFile` с фильтром .gguf), проверка формата,
  локальный SHA-256, метаданные только из заголовка; модель видна менеджеру и
  запускается через Engine API даже вне папки моделей.
- **Безопасность загрузок (§5.5)**: белый список источников (официальный
  Hugging Face), запрет http/исполняемых/не-GGUF файлов, защита от обхода
  путей, повторная загрузка проверенного файла блокируется, перезапись —
  только с явным подтверждением.
- **Локальный SHA-256 с честной пометкой**: если источник не даёт контрольную
  сумму — хеш вычисляется локально и помечается как проверка целостности,
  а не подтверждение подлинности источника.
- **Обновление каталога без обновления приложения (§8)**: локальный
  `catalog-override.json` и опциональный удалённый JSON (`models.catalogUrl`);
  без интернета каталог работает полностью на вшитых данных.

### Fixed
- Дозаполнены 3 отсутствующих LFS SHA-256 (deepseek-coder-6.7b, TheBloke).

## [0.4.0] — 2026-11-09

### Added
- **Собственный runtime llama.cpp (`lmlama`)** (`src/backends/lmlama.js`):
  авто-обнаружение llama-server (env → config → resources → PATH), запуск и
  остановка процессов, SSE-стриминг чата, выгрузка модели из RAM завершением
  процесса; Ollama больше не требуется (осталась опциональной интеграцией).
- **Парсер GGUF-заголовков без зависимостей** (`src/backends/gguf.js`):
  архитектура, имя модели, квантование, размер контекста.
- **Менеджер моделей**: сканирование папки моделей (`GET /api/models/scan` —
  размер, формат, квантование, совместимость с RAM, статус) и настоящее
  удаление файлов модели с освобождением места (`POST|DELETE /api/models/delete`).
- **Вложения в чате** (`POST /api/attachments`, `src/attachments/extract.js`):
  извлечение текста из TXT/MD/CSV/JSON/кода, PDF (inflate-потоки + Tj/TJ) и
  DOCX (ZIP + XML) без внешних зависимостей; содержимое реально передаётся модели.
- **AI Chat — главный экран** (`packages/app/src/litemind`): полноэкранный чат
  нового поколения (собственный дизайн LiteMind): широкая диалоговая область,
  Markdown/код/таблицы, история чатов и «Новый чат», выбор модели у строки
  ввода, вложения, стриминг с кнопкой «Остановить».
- Сборка llama.cpp без AVX/AVX2/FMA/F16C (цель — Intel Celeron N5095A),
  статическая линковка; runtime входит в NSIS-установщик.
- Скрипты: `scripts/build-llamacpp.sh`, E2E-тест `test/e2e-lmlama.mjs`
  (реальный GGUF: ответы, SSE, выгрузка, удаление, отмена).
- **Каталог моделей v2 — 42 модели / 143 GGUF-файла** (было 12): Qwen2.5/3/3.5,
  Qwen2.5 Coder, DeepSeek Coder и R1-Distill, Phi-3.5/4-mini, Gemma 2/3,
  Llama 3.2, Mistral/Ministral, SmolLM2/3, TinyLlama, русские Vikhr и Saiga2,
  uncensored-линейки Dolphin и Huihui (abliterated). Все ссылки — с официальных
  страниц HF и проверенных квантизаторов; у 139 файлов — SHA-256 из LFS HF.
  Явное разделение ограничений (`standard` / `reduced`), языки, теги задач,
  класс скорости, автор квантования и лицензия в каждой карточке.
- Пятиуровневая совместимость (great / ok / slow / avoid + несовместима) с
  учётом KV-кэша, буферов и резерва Windows; фильтры каталога (задача,
  ограничения, совместимость, размер, квант) в desktop-UI и веб-панели.
- Новые API: `POST /api/models/verify` (сверка SHA-256/размера скачанного
  файла с эталоном HF), `POST /api/models/run` (запуск скачанной модели без

  Q4_K_M): скачивание, сверка SHA-256 с HF, запуск на no-AVX-сборке

- CI `litemind-windows.yml`: сборка no-AVX llama.cpp, включение runtime в

## [0.3.0] — 2026-11-07

### Added
- **Adaptive Engine** (`packages/litemind-engine/src/adaptive/`):
  - контроллер сложности запроса (simple/file/project/hard) и адаптивный бюджет генерации;
  - умное уплотнение контекста (система/первая задача/недавние сохраняются; середина — сводка);
  - extractive-дайджест длинных входов;
  - честная карта возможностей runtime (`/api/capabilities`);
  - Project Context: инкрементальный индекс и поиск по проекту (`/api/project/scan|search|map`).
- **Автооптимизация модели** (`/api/optimize`): замер tokens/sec и TTFT по конфигурациям
  потоков, сохранение лучшей; живые метрики EMA в профиле модели.
- **Защита Windows**: memory-gate, контроль памяти во время генерации (MEMORY_OVERLOAD →
  автостоп + безопасная выгрузка), приоритеты процессов Ollama по профилю.
- **Профиль «Производительный»**; профиль по умолчанию — «Сбалансированный» (ТЗ §6).
- **Нативные экраны LiteMind внутри Desktop** (`packages/app/src/litemind/`):
  Мои модели, Каталог моделей, Загрузки, Железо, Мониторинг, Настройки —
  в одном окне, без браузера и `127.0.0.1:8399`-переходов.
- **Автозапуск движка внутри Electron main** (`packages/desktop/src/main/service/litemind-host.ts`).
- **Windows-установщик**: NSIS с выбором папки, ярлыками «LiteMind Engine», portable-версия;
  фирменная иконка.
- GitHub Actions: тесты движка + сборка Windows x64 (`litemind-windows.yml`).
- Документация: `docs/litemind/{ARCHITECTURE,ADAPTIVE-ENGINE,BUILD-WINDOWS}.md`.

### Changed

- Брендинг: LiteMind (title, productName, артефакты, иконки).
