# Changelog — LiteMind Engine

Формат: Keep a Changelog; версионирование SemVer.

## [0.6.4] — 2026-11-14 — компаньон LiteMind, Intelligence Layer, интернет по кнопке «земной шар», голос

Полноценный настольный ИИ-компаньон (Roamies-класс) внутри LiteMind Engine:
персонаж на рабочем столе, голосовое общение, долговременная память, задачи и
напоминания, «посмотри на экран», управление Windows — всё локально и бесплатно.
Плюс интеллектуальный слой, делающий слабые модели полезными, и чат-кнопка
«земной шар» с настоящим веб-поиском и честной погодой.

### Added
- **Intelligence Layer (дополнение ТЗ §1–§8)**: детерминированная классификация
  запроса (0 мс, без модели) → надёжные инструменты приложения (погода
  Open-Meteo, поиск DuckDuckGo, точный калькулятор, локальные часы, память,
  планировщик, экран) → краткий стабильный системный промпт (prompt-cache
  llama.cpp ускоряет первый токен) → самопроверка ответа (утечки служебных
  токенов, зацикливание, перепутанные роли, «погодные цифры без источника») с
  НЕ БОЛЕЕ чем одной исправляющей попыткой в экспертном режиме. Режимы
  Быстрый/Умный/Эксперт по-настоящему меняют работу движка.
- **Кнопка «земной шар» в чате (ТЗ §5)**: настоящий переключатель интернета для
  каждого чата. Включён — реальные источники (Open-Meteo без ключей, DuckDuckGo
  html/lite), блок «Источники» с датой получения под ответом. Выключен — модель
  честно предупреждает, что актуальные данные проверить не может, и НЕ
  выдумывает погоду/цены/новости (тест Иркутска: без интернета — отказ,
  с интернетом — данные сервиса + время наблюдения + ссылка).
- **Компаньон (Roamies-дополнение)**: персонаж-оверлей на рабочем столе
  (собственные персонажи LiteMind: Люми/Искра/Орб, размер/прозрачность/
  поверх окон/перетаскивание, полное отключение), долговременная память с
  запретными темами, задачи и напоминания (переживают перезапуск, повторы
  ежедневно/по будням/еженедельно, уведомления Windows + голос), «посмотри
  на экран» (локальный OCR Windows, скриншоты не покидают ПК), управление
  Windows с подтверждениями и разрешениями, панель компаньона с историей
  действий, горячие клавиши Ctrl+Alt+L/P/V/H/T.
- **Голос (ТЗ §2)**: локальные whisper.cpp (ASR) и piper с русским голосом
  Irina (TTS). Компоненты скачиваются ТОЛЬКО по кнопке пользователя с проверкой
  размера и SHA-256 (URL и суммы вычислены из фактических файлов источников),
  в фоне ничего не слушается: Push-to-Talk — кнопка 🎙 или Ctrl+Пробел
  (удерживать и говорить), озвучивание ответов и напоминаний отключаемое,
  скорость речи настраивается. На слабом ПК (CPU без AVX) работает в реальном
  времени для коротких фраз.
- **Агент (ТЗ v0.6.4 §6)**: пошаговый таймаут (модель не может висеть в
  «Обдумывании шага» вечно), видимые статусы этапов (анализ → поиск →
  получение источников → выполнение → готово), детерминированная маршрутизация
  погоды/поиска до модели (слабая модель получает готовые факты), новые
  сервисные инструменты: weather, web_search, calculator, memory_save/
  memory_search, task_create/task_list, screen_look.

### Fixed
- **Значок OpenCode на панели задач (ТЗ v0.6.4 §2)** — настоящая причина: окно
  регистрировалось под чужим AppUserModelID `ai.opencode.desktop` (constants.ts),
  а ярлык установщика нес `ai.litemind.desktop`. У пользователя с установленным
  OpenCode Windows связывала чужой AUMID с его значком — LiteMind рисовался
  значком OpenCode. Теперь AUMID окна = ai.litemind.desktop(.dev/.beta),
  userData остаётся в историческом каталоге (STORAGE_ID) — чаты и настройки
  при обновлении не теряются, закреплённый ярлык «LiteMind Engine» переписывается
  установщиком на новый exe и корректный AUMID.
- **Качество ответов и формат диалога (ТЗ §4)**: у чата не было системного
  промпта вовсе — модель получала голую историю. Теперь: короткий стабильный
  системный промпт по семейству модели, stop-последовательности чат-шаблонов
  («<|im_end|>», «### Instruction:» и т.п. не попадают в ответ), параметры
  против повторов (repeat_penalty/presence/frequency), очистка служебных
  фрагментов, самопроверка; маленькая модель 0.5B честно помечается ограничений
  и не выдаётся за сильного агента.
- **Скорость локальных моделей (ТЗ §3)**: главный источник медленного первого
  токена — длинный промпт на CPU без AVX. Стабильный короткий префикс + кэш
  llama.cpp убирают повторный prefill системного промпта на каждом сообщении;
  модель остаётся загруженной между сообщениями (idle-unload настраивается
  профилем); история уплотняется адаптивным контроллером без лишнего контекста.

### Security
- Веб-инструменты работают только через управляемый контекст (SSRF-защита
  публичных хостов), интернет по умолчанию выключен; в поисковый запрос уходит
  только сам запрос — история чата и личные данные в сеть не передаются.
- Управление окнами и экраном — только по разрешениям компаньона, с
  подтверждением каждого действия; память имеет запретные темы.


## [0.6.3] — 2026-11-14 — исправления реального ПК: значок, кнопки окна, навигация чатов, чат с моделью, запуск llama-server

Баги из ТЗ §1, обнаруженные на реальной машине (Windows 11, N5095A без AVX):
значок OpenCode в панели задач, светлая системная панель кнопок окна поверх
тёмного интерфейса, «мёртвые» переходы между чатами, `Model "[object Object]"`
при отправке сообщения и `connect timeout` при запуске ИИ-агента.

### Fixed
- **Значок OpenCode вместо LiteMind (ТЗ §1.1)**: в репозитории не было
  committed-набора брендинга — `script/copy-icons.ts` копировал апстрим-иконки
  OpenCode (`icons/{channel}`) в `resources/icons`, и exe/установщик/окно
  получали значок OpenCode (скрипт сам предупреждал об этом в логе). Теперь
  оригинальный знак LiteMind (искра ✦ в фирменном градиенте #6C8CFF→#9A6CFF
  на тёмной плитке, геометрия построена параметрически, без заимствований)
  закоммичен в `resources/icons` (icon.ico 256/128/64/48/32/16 + PNG 16–256),
  каталог исключён из .gitignore — `copy-icons.ts` сохраняет эти файлы поверх
  апстрим-копий, electron-builder встраивает их в exe/NSIS/ярлыки. AppUserModelID
  (`setAppUserModelId(APP_ID)`) уже согласован с ярлыком установщика и оставлен
  без изменений намеренно: смена appId переносила бы %APPDATA%-каталог
  пользователя и уничтожала историю чатов (ТЗ §8 запрещает терять данные).
- **Светлая системная панель кнопок окна на тёмном интерфейсе (ТЗ §1.2)**:
  цвета titleBarOverlay выбирались по теме СИСТЕМЫ (`nativeTheme`), а
  интерфейс приложения тёмный — на светлой Windows панель min/max/close
  рисовалась светлой. Оверлей теперь следует теме ПРИЛОЖЕНИЯ: `appOverlayMode()`
  (по сохранённому фону рендерера, тёмный по умолчанию) в `platformFrame`
  раннего и основного окна; интерфейс сообщает тему и фон через новый мост
  `litemindEngine.setWindowTheme(mode, background)` (preload → `litemind:set-window-theme`
  → setTitlebar/setBackgroundColor) — переключение Тёмная/Светлая/Система в
  приложении мгновенно перекрашивает системные кнопки.
- **Чат не общался с моделью: `Model "[object Object]"` (ТЗ §1.4)**:
  `runCompletion()` читала голое имя `model`, которое разрешалось в глобальный
  DOM-элемент `<select id="model">` (браузер создаёт `window.model` по id):
  `JSON.stringify(select)` давал `{}`, и бэкенд отвечал
  `Model "[object Object]" is not available locally`. Теперь модель передаётся
  явным строковым аргументом, на границах добавлена нормализация: `runCompletion`
  (аргумент → chat.model → селектор), `handleCompletions` в API (`{id:…}`/строка
  → строка), `engine.generate` (объект с `id` → строка, иначе честный
  BAD_MODEL 400). Ошибка «модель не найдена» локализована и для llama.cpp
  советует свои разделы («Модели» → «Каталог»/«Свой GGUF»), а не `ollama pull` —
  пользователь уже скачал GGUF-файл (regression-тест: подсказка без «ollama pull»).
- **ИИ-агент падал с `connect timeout` (ТЗ §1.5)**: таймаут на ЗАГОЛОВКИ ответа
  llama-server был захардкожен 60 с — меньше любой другой границы движка
  (загрузка модели 180 с, requestTimeoutMs профилей 600–1800 с). На CPU без
  AVX prefill системного промпта агента идёт дольше минуты: соединение
  установлено, процесс жив, llama-server ещё считает промпт — а запрос уже
  падал «connect timeout … процесс мог завершиться» (ложь дважды). Теперь
  `headersTimeoutMs` конфигурируем (`config.backend.headersTimeoutMs`, дефолт
  10 мин, пробрасывается registry), а сообщение об истечении честно объясняет:
  модель ещё обрабатывает запрос (prefill) — подождите, уменьшите контекст или
  уберите большие вложения. Готовность сервера по-прежнему проверяется реальным
  /health === ok (не «процесс создан»).
- **Навигация чатов (ТЗ §1.3)**: переименование чата и ввод пути GGUF
  использовали `window.prompt()`, который в Electron не поддерживается и
  бросает исключение — кнопка «Переименовать» молча ничего не делала.
  Заменено собственным модальным вводом (`modalPrompt`, Esc/Enter/клик мимо).
  «Новый чат» и клик по чату в списке теперь открывают вкладку чата из любого
  раздела — раньше из «Моделей»/«Агента» менялась только активность в списке,
  что выглядело как «кнопка ничего не делает».

### Tests
- +5 регресс-тестов `test/regression-v063.test.js`: нормализация модели
  в `engine.generate` ({id} → строка, `{}`/число → BAD_MODEL), ошибка
  «модель не найдена» llama.cpp без «ollama pull», дефолт и проброс
  `headersTimeoutMs` через config → registry. Полный набор: 230/230.

## [0.6.2] — 2026-11-13 — исправление краша запуска моделей, обнаружение моделей, автозапуск

### Fixed
- **Критический краш llama-server (0xC0000135 STATUS_DLL_NOT_FOUND)** (ТЗ v0.6.2 §1):
  llama-server умирал через 0,4 с с кодом 3221225781 — на чистой Windows 11 рядом
  с исполняемыми файлами отсутствовали runtime-DLL: VC++ (msvcp140, vcruntime140,
  vcruntime140_1, vcomp140) и OpenSSL (libssl-3-x64, libcrypto-3-x64). Все
  зависимости теперь кладутся рядом с llama-server.exe и sd.exe (app-local
  deployment) и входят в установщик; OpenSSL берётся из пути CMakeCache — ровно
  та версия, с которой слинкован движок. CI-верификация падает, если хоть одна
  runtime-DLL не попала в установщик.
- **Понятная диагностика крашей**: NTSTATUS-коды расшифровываются в сообщениях
  (3221225781 → 0xC0000135 STATUS_DLL_NOT_FOUND + подсказка, что делать),
  signed/unsigned варианты кода.
- **Скачанные модели видны сразу** (ТЗ §2): селектор моделей = runtime + скан
  папки моделей (/api/models/scan) с дедупликацией по пути; работает и при
  незапущенном runtime (503). Списки обновляются сразу после скачивания/установки
  (refreshScanModels).
- **Автозапуск модели при выборе** (ТЗ §2): выбор модели в чате и «Открыть в
  чате» стартуют модель (POST /api/models/run), приложение ждёт готовности
  («Запуск модели…»), уже запущенная модель не перезапускается повторно,
  реальная ошибка API показывается красной строкой над вводом.
- **RUNTIME_BUSY**: смена профиля на работающем движке больше не отклоняется
  собственной генерацией инициатора; отказ остаётся только при реальной
  параллельной генерации.
- **Генерация изображений из установленного приложения**: sd.exe ищется в
  каталоге extraResources установщика; /api/image/generate разбирает JSON тела
  запроса (раньше любой запрос падал 400 «Введите текстовое описание»);
  applyPriorityToPid возвращает Promise — прежний undefined.catch ронял
  генерацию.
- **Тихая деинсталляция зависала на диалогах** (ТЗ §1.6–1.7): вопросы «Удалить
  также модели?» и «Удалить настройки?» в customUnInstall были без переключателя
  /SD — по правилам NSIS такой вопрос показывается даже в тихом режиме (/S),
  и Uninstall LiteMind.exe бесконечно ждал клика (на CI прогоны №9–№13 снимались
  по таймауту на этом шаге). Теперь /SD IDNO: тихое удаление сохраняет модели и
  настройки по умолчанию (как требует ТЗ), интерактивные пользователи по-прежнему
  видят оба вопроса.

### Added
- **Панель «Ресурсы и профиль»** (Мониторинг): эндпоинт GET /api/resources —
  RAM/CPU из сэмплера, фактические параметры runtime, скорость генерации
  (tokens/sec), применённый профиль; без внешних подпроцессов. Опрос раз в 3 с
  и только при видимой вкладке.
- **Надёжность интерфейса**: безопасная привязка обработчиков (сбой одного
  не вешает остальные кнопки), localStorage и сохранённые чаты под try/catch,
  нормализация повреждённых данных; иконка окна Windows из resources/icons
  (extraResources) ставится только при существовании файла.

## [0.6.1] — 2026-11-11 — AI Agent, Model Discovery, управляемый интернет, установка одним файлом + Этап 2 «Глубокая оптимизация GGUF Runtime»

### Added
- **Model Discovery — «Новые модели»** (ТЗ v0.6.2): приложение само следит за
  открытыми источниками GGUF-квантов (Hugging Face Hub API — бесплатно, без
  регистрации). Автопроверка раз в сутки (настраивается 6–168 ч) + кнопка
  «Проверить новые модели». Качаются ТОЛЬКО метаданные (названия, размеры,
  SHA-256); сами модели — исключительно по кнопке пользователя. Каталог живёт
  в %APPDATA%\LiteMind\discovery и переживает перезапуск; сбой сети не портит
  ранее найденное. Фильтры: новинки, обновления, совместимые с моим ПК
  (оценка по реальному железу), общение/код/тексты, быстрые, Dolphin/Huihui,
  уже скачанные. Скачивание найденной модели — тем же загрузчиком с паузой,
  докачкой и проверкой SHA-256; повторное появление файла не создаёт дубль,
  изменившийся в источнике файл показывается как «Обновление» с историей
  прежних версий (до 3).
- **AI Agent — полноценное диалоговое рабочее пространство** (ТЗ v0.6.1 + дополнения):
  реальный цикл Agent → Tool → Result с исполнением инструментов. Раздел «AI Agent»
  в боковой панели рядом с Chat; собственные диалоговые задачи с историей,
  уточнениями во время выполнения и восстановлением после перезапуска.
  Инструменты: list_files, read_file, write_file, edit_file, delete_file, search,
  terminal, web_fetch, github, ask_user, done. Протокол TEXT/ACTION/ASK/DONE
  устойчив на малых GGUF-моделях (Qwen3-0.6B и совместимые).
- **Безопасность агента**: изменение файлов и команды терминала — только после
  подтверждения пользователя с показом unified-diff; перед изменением создаётся
  резервная копия (откат через Workspace); пути строго внутри папки проекта;
  лимиты шагов/времени; кнопка остановки убивает и запущенные команды.
- **Управляемый интернет** (ТЗ §7): по умолчанию выключен. Чтение веб-страниц
  (html→текст) и публичный GitHub API (repo/readme/contents/commits/search).
  Защита SSRF: локальные и приватные адреса заблокированы; опциональный
  GitHub-токен хранится только в config.json и не логируется.
- **Модель-менеджер**: автоматическая проверка SHA-256 после скачивания
  (эталон из каталога; несовпадение честно помечается ошибкой).
- **Установщик одним файлом**: LiteMind-Engine-Setup-x64.exe (NSIS-мастер с выбором
  папки, ярлыками и запуском после установки); пользовательские данные
  (%APPDATA%\LiteMind, модели) переживают удаление и переустановку.
- **Настройки**: раздел «Интернет» с явным включением доступа и тумблером GitHub.
- **Смоук в Windows CI**: реальная многошаговая задача агента на живой модели
  (создание файла + запуск команды + уточнение + остановка + история + чат
  параллельно), тихое удаление с проверкой сохранности данных и переустановка.

### Fixed
- Ошибка инструмента больше не прерывает цикл агента — текст ошибки уходит модели
  для корректировки следующего шага (до 3 нечитаемых ответов подряд).
- **«Пустой ответ» у reasoning-моделей (Qwen3 и т.п.)**: адаптивный контроллер
  повышал явный лимит клиента `max_tokens` до пола 192 токенов (16 → 192).
  У думающих моделей весь вынужденный бюджет съедали `<think>`-размышления,
  которые клиенту не пересылаются, — пользователь получал пустой ответ,
  а замеры показывали честно отработавшие 192 токена. Теперь явный лимит
  клиента — жёсткий потолок (OpenAI-совместимость): контроллер может его
  только уменьшать под сложность задачи; пол minOutputTokens применяется
  лишь к внутреннему дефолту, когда лимит не указан.
- **Обрыв генераций на 60-й секунде**: connect-таймаут в бэкенде жил весь стрим
  и убивал ответы длиннее минуты. Таймер теперь снимается сразу после
  заголовков ответа; генерацию сторожит watchdog бездействия, запускаемый
  от первого токена (медленный prefill длинного промпта больше не рвётся).
- **Таймауты запроса** подняты с 120/180/300 с до 600/900/1800 с: слабая
  модель на 2 т/с писала ответ 4–6 минут — прежние лимиты обрывали
  легитимные ответы. Автовыгрузка модели отодвинута до 15/30/60 мин простоя.
- **Параметры профиля применяются по-настоящему**: llama-server больше не
  переиспользуется с чужими настройками — при изменении потоков/batch/mmap/
  кэша/контекста (args-key) runtime честно перезапускается с новыми
  аргументами. Раньше автооптимизация потоков измеряла одну и ту же
  конфигурацию трижды (перезапуска не было).
- **Мониторинг CPU на Windows**: метрики переведены на чистый Node (os.freemem
  + дельта os.cpus). Раньше каждые 2 с запускался powershell с WMI-запросами,
  который на слабых машинах выходил за таймаут → CPU показывал 0% при
  работающей генерации (то, что пользователь и наблюдал).
- **numBatch игнорировался** — теперь передаётся в llama-server.

### Added (Этап 2 «Глубокая оптимизация GGUF Runtime»)
- **Трассировка стадий запроса** (§2): очередь → память → запуск runtime →
  промпт → первый токен → генерация, с честными «недоступно» для неизмеримого;
  `GET /api/perf`; разбор собственных таймингов llama.cpp (prompt eval /
  eval time) из stderr сервера; TTFT разделён на «с холодным стартом» и
  «после загрузки модели» — загрузка весов не выдаётся за медленную генерацию.
- **Профили с реальными параметрами** (§8): Бережный → 2 потока генерации на
  N5095A и приоритет ниже обычного; Сбалансированный → 3 потока + prefill на
  всех ядрах; Производительный → 4 потока, batch 2048, cache-reuse 256.
  Мониторинг показывает фактически применённые параметры и причину последнего
  перезапуска runtime.
- **mmap-политика «auto»** (§3): модели, заведомо помещающиеся в RAM
  (порог max(1 ГБ, 25% RAM)), грузятся без mmap — последовательное чтение
  быстрее холодного mmap на слабых дисках и ускоряет генерацию (веса уже в
  RAM); большие модели остаются на mmap, чтобы Windows могла вытеснять
  холодные страницы.
- **Динамический резерв RAM** (§3/§11): при признаках paging и высокой
  загрузке системы резерв для Windows растёт (до +50%), при спокойной системе
  равен базовому резерву профиля.
- **Диагностика в интерфейсе** (§12): панели «Runtime — фактически применённые
  параметры», «Стадии последнего запроса», расширенные средние по генерации;
  под ответом чата — честные замеры движка (загрузка модели, т/с, промпт).
- **Честная диагностика GPU** (§10): llama-server опрашивается через
  `--list-devices`; комплектная CPU-сборка честно сообщает «устройств нет»;
  автовключение iGPU не выполняется.
- **Приоритет по PID** сразу после запуска llama-server (§4/§11).
- **Сборка CI с вариантами ядер** (§4): GGML_BACKEND_DL + GGML_CPU_ALL_VARIANTS
  — база остаётся без AVX/AVX2 (совместимость с N5095A), но llama.cpp сам
  выбирает лучший поддерживаемый процессором вариант (на N5095A — sse42).

### Changed (Этап 2)
- Потоки prefill (`--threads-batch`) — все ядра (короткая фаза), потоки
  генерации — по профилю (2/3/4 на N5095A).
- batch/ubatch по профилю 512/256, 1024/512, 2048/512 (раньше numBatch
  128–512 был ниже дефолтов llama.cpp и тормозил prefill).
